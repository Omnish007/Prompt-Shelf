## Security review

Implemented defense-in-depth for Electron defaults, validated IPC sender origins and payloads, no direct filesystem/raw SQL renderer access, a restrictive CSP (with `unsafe-inline` currently retained for SSR hydration compatibility), blocked cross-origin navigation and remote new windows, HTTPS-only external link handling, secure OAuth state/PKCE checks, restricted Drive scope, bounded JSON file sizes, transaction-backed library writes, and encrypted token storage.

Residual risk: `better-sqlite3`, Electron, Vite/TanStack, and all transitive dependencies need a current `npm audit` / advisory review after installation. This environment did not resolve the npm registry, so no dependency audit result is claimed. Google OAuth setup and refresh-token behavior need live credentials and a real Ubuntu desktop keyring to validate.

## Performance review

The search now uses a memoized weighted Fuse.js index over the visible library, prioritizing titles while also matching descriptions, tags, prompt bodies, and collection names. Search allows minor spelling errors and intersects terms so every query word must match. At 104 built-ins, the index is expected to be small; large user-created libraries still need measurement against representative data before making performance claims. Desktop snapshot writes are transactional but replace all library records on each debounced commit; this deliberately favors a straightforward consistency model for typical libraries. If real profiling shows slow writes at large scale, migrate to entity-level IPC writes and enable an FTS5 search index if the bundled SQLite build supports it. No performance benchmark was measured here, so no numeric performance claim is made.

## UI, accessibility, and interaction-performance pass (2026-10-15)

- Rebuilt the theme layer around semantic OKLCH tokens, with independent light and dark ramps rather than simply inverting colors. Violet-blue anchors the brand, cool neutrals structure surfaces, teal indicates success, amber communicates caution, and red is reserved for destructive actions. A hue alone never communicates status; status tokens pair color with visible text/icons.
- Split app-owned UI into prompt-shelf feature modules and separate theme/base/utility/component stylesheets. The largest app-owned feature files are `CollectionPanels.tsx` (283 lines), `PromptShelf.tsx` (270), `store.ts` (268), `PromptListPane.tsx` (253), and `PromptEditor.tsx` (228). Existing generated shadcn primitives remain intact to avoid forking upstream component implementations.
- Replaced the all-element/all-property transition with transitions limited to interactive visual properties. Added off-screen prompt-row rendering hints, reduced-motion handling, and a search-index memoization boundary so typing does not rebuild the full index.
- The editor now holds an immediate local draft and debounces persisted store writes while typing. Explicit save, browser unload, and Electron close paths request a synchronous draft commit before flushing persistence. This improves the hot typing path, but actual latency still needs profiling on the supported desktop/browser setups and with large user libraries.
- Fixed the React hook-order hazard during initial hydration by ensuring the component reaches the same hooks before choosing the loading or loaded render. Initial library loads are coalesced to avoid duplicate work under React StrictMode; duplicate IndexedDB writes were removed.
- Swapped the custom modal implementation for the installed shadcn/Radix Dialog for its standard focus, escape-key, and focus-return behavior. Used installed shadcn components where semantically appropriate, including `Dialog`, `AlertDialog`, `Button`, `Card`, `Input`, `Select`, `ScrollArea`, `Progress`, `Skeleton`, `Badge`, `Switch`, `Tooltip`, and `Sonner`.
- Added `scripts/check-theme-contrast.mjs` and the `npm run theme:contrast` command. The current semantic token pairs pass the configured WCAG-oriented thresholds: normal text at least 4.5:1, input boundaries/focus indicators at least 3:1. This is a token-pair check, not a full rendered-page WCAG audit; hover, disabled, overlay, and every component-state combination still need browser-based manual/accessibility testing.
- Added a hydration regression test at `src/test/prompt-shelf-load.test.tsx` that checks for React hook-order errors, along with a seed-version upgrade regression test. Source syntax transpilation and the theme contrast script pass. Vitest, the Vite production build, ESLint, and browser performance measurements remain unverified because this environment's partial dependency installation does not include runnable `vitest`, `vite`, or `eslint` binaries.

- Changed library-load failure handling to leave the store unloaded instead of silently substituting starter content. The recovery view explains that the library was not intentionally reset, exposes a bounded technical diagnostic, and retries the actual persistence read. This avoids allowing a later save to overwrite a library that could not be read.
- Added regression coverage for a transient desktop-storage load failure followed by a successful retry.
- Reworked the home screen around a search-first hero, compact library overview, and three action-oriented prompt groups instead of six equally weighted summary panels. The local prompt-quality section remains available.
- Added a visible local-save status in the desktop sidebar; failed writes can be retried explicitly. Added a keyboard skip link and semantic labels for navigation landmarks.
- Theme application now runs in a client layout effect to reduce the possibility of a one-frame wrong-theme flash after refresh.
- Improved route retry ordering by awaiting router invalidation before resetting the error boundary. Full proof still requires running the app in a complete dependency-backed browser/desktop environment.
